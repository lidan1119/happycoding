# 设计

## 页面与视觉
单页面三阶段：店门与货架 → 购物篮确认 → 打印小票。首屏直接展示标题、100 币余额、开场白和第一排商品，不设置阻碍体验的登录或教程。

采用午夜便利店风格：深靛蓝背景、奶油色价签、荧光绿色余额与珊瑚色提示。货架卡片像奇怪的零食包装，小票采用纸白色、等宽文字和锯齿纸边。桌面右侧固定购物篮，手机底部显示篮子摘要，展开后查看完整内容。动效用于选中反馈和打印过程，尊重 reduced-motion；声音默认关闭，第一版不必加入音效。

## 交互规则
初始 100 币，最多选 5 件，每件限购 1 次。再次点击已选商品可移除。余额不足或达到上限时给出明确原因，不改变购物篮。副作用始终可见，避免只在悬停时显示。空篮子不能结账，可随时重置并确认；结账前可返回修改。

隐藏组合在结账时揭晓，不额外扣款。命中多个组合时按照固定优先级展示最多 2 个；未命中时给出与所选商品相关的保底故事。相同选择生成相同结果，重试不能通过随机刷新改变结果。故事采用手工内容和规则，不调用外部 AI。

## 数据与实现方向
Vite + TypeScript，优先原生 DOM 与 CSS，避免为小型游戏增加不必要框架。商品与组合为类型化数据；预算、限购、组合匹配、结算为独立纯函数。图片主要由 CSS 和本地 SVG 构成，无第三方字体或图像运行时请求。

小票 PNG 使用 Canvas 绘制，先等待本地字体就绪，对中文换行、长文案和高像素密度做处理；另提供复制文字及选中文本备用路径。小票不含日期或个人信息，不要求昵称。

localStorage 仅保存版本化的商品 ID 列表；读取失败、格式损坏或旧版本 ID 无效时安全恢复默认状态，始终重新计算金额，不能信任缓存余额。存储不可用不影响游玩。

## 部署
构建产物 dist，通过 GitHub Actions 官方 Pages 部署流程发布。Vite 使用适配项目子路径的相对 base，支持 /happycoding/。不使用需要服务器重写的前端路由。首次部署需核实仓库 Pages 设置及当前认证的管理权限；未获取真实访问证据前不得声称已上线。

## 主要风险与处理
趣味不足：先完成 18 件商品和 6 个组合文案评审，再做页面。小票文字溢出：按测量宽度换行并动态计算画布高度。社交分享能力不同：第一版用下载 PNG 与复制文字，不把系统分享 API 当必需项。范围扩大：先完成完整单人闭环再考虑音效、更多商品与每日挑战。
